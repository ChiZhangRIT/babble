# 牙牙呓语

专门用来记 NN 说的梦话：夜里最快地把声音录下来，白天再补上原话，几年后还能按日期或者关键词翻出来，再听一遍。

- 网页 App（PWA），不需要编译，也不用上架 App Store；部署到 GitHub Pages 就能在 iPhone、iPad、Mac 上用，添加到主屏幕 / 程序坞后和普通 App 一样打开，没网也能打开
- 梦话和录音保存在自己设备的浏览器里；开启同步后，另存一份到你自己的 GitHub 私有仓库，不经过任何第三方服务器
- 你和 NN 两个人的 iPhone、iPad、Mac 用同一个同步码，看到的是同一本
- 界面有简体中文、繁體中文（台灣）、English 三种（「设置 → 外观」切换）；你写的原话永远原样保存，不做简繁转换，引号、标点也不会被「修正」

## 怎么用

底栏只有三个：**呓语**（列表 / 日历）｜ 中间的**猪鼻子**（录音）｜ **设置**。iPad 和 Mac 上换成侧栏，窗口够宽时左边列表或日历、右边详情。

### 记一条

列表上的 ＋「记一条」。日期默认今天（必填），时间可以不填。原话框上面有 `👰🏻‍♀️ NN` 和 `🥷🏻` 两个按钮，点一下就插入一行、光标停在引号中间；下面一排表情（🤯 🫨 😲 🤭 😂 🥲）插入「🥷🏻 + 表情」那一行。也可以在详情页的 `⋯` 里「添加录音（文件）」。

原话就按你在备忘录里一直以来的写法写，App 会画成聊天气泡（下面是编出来的例子）：

```
👰🏻‍♀️“今天吃什么”          ← NN 说的话：左边的气泡
🥷🏻“想吃什么呀？”          ← 你问的：右边的气泡
👰🏻‍♀️ 皱了皱眉              ← 动作（没有引号）：浅浅的「动作」气泡，普通字体
👰🏻‍♀️ 指着窗外 “下雨了”     ← 混着写：引号里的楷体，引号外的动作小一点、淡一点
🥷🏻 🤯                     ← 只有表情：显示成一个大表情
过了一会儿..                 ← 不以表情开头的行：居中的小字旁白
                             ← 空一行：同一晚的两段之间隔开
```

表情带不带肤色、带不带变体符号都认得（👰‍♀️ / 👰🏻‍♀️ / 👰🏻‍♀ 都算 NN）。在「设置 → 称呼与表情」改了表情，旧的表情还会继续被认出来，以前写的不用改。

### 对话里的动作和说的话

**引号里是说的话，引号外是动作或环境**。说的话用楷体；动作、环境、旁白用普通字体，小一点、淡一点，像剧本里的舞台说明（不用斜体，中文斜体不好看）：

- 一整行都是动作（`👰🏻‍♀️ 揉了揉眼睛`）：浅浅的、没有底色的「动作」气泡，一眼就和说的话分开
- 混着写（`👰🏻‍♀️ 指着窗外 “下雨了”`）：同一个气泡里，「指着窗外」是普通字体，「“下雨了”」是楷体
- 没有表情开头的旁白（`过了一会儿..`）：居中的小字；旁白里带引号的那几个字照样是楷体
- “” 「」 『』 "" ＂＂ ‘’ 都算引号，「」里面套『』也行
- 引号没配对也认得：只写了后引号的（`她说了”`）从行首到后引号都算说的话；没写后引号的到这一行末尾都算说的话；行首或空格后面的 ” 当前引号用

详情页、列表卡片、修改记录的预览里都这样显示，深色、夜间也看得清。只是显示不一样，原话一个字都不改。

### 录音

点中间的猪鼻子进录音页：整页近黑、字很暗，不会晃醒人。点「开始录音」就开始录，默认是边录边写（见下一节）；不想写就点下面的「只录音」，录音时下面大半个屏幕都是「停止并保存」，摸黑也点得到（会记住，想写时点「边录边写」）。左上角的 ✕ 要长按 1 秒才会丢弃。

- 录音时屏幕保持常亮，每秒存一小段到手机上；录满 10 分钟自动停（「设置 → 夜间 → 最长录音」可以改）
- 停下后显示「已保存 0:42」，可以「再录一段」（接到同一条里）、「整理好了」或「完成」
- 录好的自动建一条**待整理**，日期和时间来自录音开始的时刻（凌晨 3:10 录的就记在当天，显示「凌晨3:10」）
- 夜间时段（默认 21:00–07:00）打开 App 会直接进录音页、全 App 变深色，都可以在「设置 → 夜间」关掉
- 第一次录音要允许使用麦克风

### 边录边写

听着 NN 说梦话、一边录一边把她说的打下来：

- 录音页点「开始录音」后，顶上一条是红点、计时、音量条和「停止」，下面就是写原话的地方（和「记一条」一样有 👰🏻‍♀️ / 🥷🏻 按钮和反应表情，楷体、暗色）。光标已经在「👰🏻‍♀️ “”」的引号中间，直接打字
- 弹出键盘时「停止」也一直在最上面；打字不会打断录音
- 停下后录音和写的字存进同一条（待整理）；「再录一段」还是同一条、写字的地方不变，停了以后也能接着补
- 可以先写再点「开始录音」，写的字照样留着；写了字没录音就离开，也会存成一条待整理（可以撤销）
- 写的字随手存在手机上（每 0.4 秒、切到后台时），App 中途被系统关掉，下次打开会把字和录到的那段一起放回同一条
- 「记一条」和编辑页里也能录：原话上面的「🎙 录一段」，不离开编辑页就录，录着也能接着写。已有的条目录好就马上接上；新的一条跟着「保存」一起存，没保存就离开也会单独存成一条待整理，不会丢
- 打字的咔嗒声会被录进去、也可能吵醒 NN：「设置 → 声音与触感 → 键盘反馈」里关掉「声音」（App 的「设置 → 夜里录得更快」里也有这条提示）

### 待整理

列表顶上的「待整理 N 条」点进去：听一遍（小声的听不清可以切到「均衡」），把原话打进去，点「整理好了」。语音备忘录自带的转写可以粘贴到「草稿」里当参考，草稿永远不会覆盖原话。

### 给录音改名

详情页每段录音上面是它的名字（导入的录音默认是原来的文件名，App 里录的是「录音 1」「录音 2」）。点名字或旁边的 ✎ 就能改；空着保存就回到默认名。编辑页的录音列表里也能改（跟着「保存」一起存）。改名会同步、会记进「修改记录」。分享录音、导出备份时用这个名字当文件名（`/\:*?"<>|` 这些文件名里不能用的字符会换成空格，最长 80 个字）；没改过名的用原来的文件名，「新录音 3」这种默认名和 App 里录的还是用日期加标题或第一句。同步到 GitHub 的文件还是按内容起的名字，不会跟着改。

### 音量均衡（听不清的时候）

梦话常常一句很小声、下一句突然很大声。把播放器右边的「原声」切成「均衡」：每一句都调到差不多的音量，小声嘀咕的放大、突然很大声的压低，按手机现在的音量听，每句都差不多响，不用一会儿调大一会儿调小。

- 只影响播放，存着的录音一点不变；随时切回「原声」
- 放着的时候也能切，接着刚才的位置放。第一次切要先把整段录音处理一下（显示「处理中…」，这期间原声照常放），之后再切就是马上的
- 选过一次，以后所有录音都按这个放，列表卡片上的 ▶ 也一样（每台设备各自记）
- 小声的那几句放大时，背景的沙沙声也会跟着大一点，这是正常的

### 语音转文字（草稿，在本机识别）

有录音的条目，每段录音下面有「转成文字（草稿）」：在这台设备上用 Whisper 把录音识别成文字，**录音不会上传到任何地方**。梦话常常含糊，识别出来的只是草稿，可能写错，但能省掉从头打字的功夫。

- **第一次用要先下载模型**：从 Hugging Face 下载一次（iPhone、iPad 上标准约 76 MB；Mac 上用显卡加速时约 199 MB），存在这台设备上，之后不联网也能用。最好连着 Wi‑Fi 时先在「设置 → 语音转文字」点「现在下载」，夜里就不用等
- 识别时显示进度（下载模型 x% / 识别中… 第 2 / 5 段），边识别边出字，随时可以「取消」；识别中可以离开这一页，做完会自己写进那一条的草稿
- 只把有人说话的地方交给模型，每段单独识别；只有杂音的录音会提示「没听出有人说话」，不会编出一句「谢谢观看」
- 结果只进**草稿**，原话一个字不动。草稿就在录音下面，可以直接「修改」（一边听一边改）；改好了点「填进原话」，每一行会写成 `👰🏻‍♀️“……”` 接在原话后面，再到编辑里把你自己说的那几行改成 🥷🏻。填错了可以撤销
- 一条有几段录音时，各段的结果按录音顺序拼在草稿里，中间空一行；重新识别一段只换掉那一段。草稿手动改过（或者是粘贴的语音备忘录转写）的话，新的结果接在后面，原来的不动
- 界面是简体中文时，识别结果里的繁体字会换成简体（Whisper 认出来的字本来简繁混着）；界面是繁体中文时不转换
- 模型：**标准**（whisper-base）适合 iPhone、iPad；**更准**（whisper-small）对含糊的话认得更好，但更慢、更占内存，只在 Mac 上提供（iPhone / iPad 上内存不够）。Mac 上有显卡加速（WebGPU）时会用显卡，快很多，但模型要多下载一些（标准约 199 MB、更准约 393 MB）；「设置 → 语音转文字 → 用显卡加速」可以关掉。显卡出错时自动改用处理器重来
- 不想占地方了：「设置 → 语音转文字 → 模型文件 → 删除」，以后要用会再下载
- 大概要多久：iPhone 上每段说话（最长 28 秒）约 3–4 秒，第一次还要多几秒载入模型；Mac 上用显卡不到 1 秒

### 搜索

搜索框直接打字，简体繁体互通（搜「梦话」也能找到「夢話」），会搜标题、原话、「那天的背景」和草稿。下面的 ⭐ 收藏 / 🎙 有录音 / 待整理 可以叠加筛选。

标题可以不填：没填的就不显示标题，卡片上直接是原话的前几句。

### 按日历看

「呓语」右上角的「列表 | 日历」切到「日历」（下次打开还是日历）。

- 有梦话的日子是浅玫瑰色的圆，下面的小圆点是条数（3 条以上加「+」），右上角的小麦克风表示那天有录音；待整理的也算。今天画一圈
- 点一天，下面列出那天的梦话（和列表里一样的卡片），点进去看详情；点一个没有梦话的日子，可以直接给那天「记一条」
- ‹ › 翻月，手机上左右滑也行，「今天」回到今天；点月份标题看全年 12 个月，点哪个月就跳过去
- 这个月还没有的话，会提示最近一条在哪天，点一下就过去
- iPad、Mac 窗口够宽时，左边是日历、右边是点开的那条

### 删除

删除的条目先进「设置 → 数据 → 最近删除」，随时可以恢复；刚删完的 10 秒内也可以直接点「撤销」。

### 修改记录与「这台设备」

每条梦话的「⋯ → 修改记录」能看到以前的每一版：什么时候、谁、用哪台设备改的，改了标题 / 原话 / 背景 / 录音 / 草稿……原话按行标出加了什么、删了什么。点开一版能看当时的样子，「恢复这个版本」就改回去（恢复本身也能撤销，也会记成新的一版）。详情页最下面有一行小字「最后修改：谁 · 哪台设备 · 什么时候」，删除的梦话在「最近删除」里也写着是谁删的。

- **这台设备**：「设置 → 这台设备」填设备名（默认是 iPhone / iPad / Mac）和「谁在用」（你或者 NN，用「称呼与表情」里的名字和表情）。只存在这台设备上，不同步。第一次在一台设备上改梦话时会问一句「这台设备是谁在用？」，也可以「以后再说」
- 旧版本保存在这台设备上（每条最多 100 版，不同步）；开了同步的话，还能点「从云端历史找更早的版本」，从数据仓库的提交记录里一版一版往前找，别的设备上改的也找得到
- 以前的条目、旧版本 App 改的，详情页不写是谁改的，修改记录里写「不知道是谁改的」，不会写错人

为什么不做「改之前要输密码」：同一个同步码的设备本来就能直接改仓库里的数据，App 里的密码挡不住真想改的人，反而自己半夜改个错字也得输密码。所以换了个思路：谁改的、改了什么都记下来，改坏了、删错了随时能改回去。真要防止别人动手，靠的是同步码只给信得过的设备。

## 夜里最快的录法

网页 App 没法从锁屏、操作按钮或控制中心直接打开，一锁屏录音也会停（见「已知限制」）。所以手机锁着的时候，用系统自带的**语音备忘录**录，早上再导入，最后都进同一个「待整理」。

**操作按钮**是 iPhone 15 Pro、15 Pro Max 和 iPhone 16 及之后的机型左侧、原来静音开关位置上的那个按钮，可以设成一按就做某件事。iPhone 15 / 15 Plus 没有，还是静音开关。

- **有操作按钮的 iPhone**：「设置 → 操作按钮」选「语音备忘录」。夜里按住操作按钮就开始录，说完再按一下停，接着睡
- **iPhone 15（没有操作按钮）**：把锁屏底部的一个按钮换成语音备忘录：长按锁屏 →「自定」→「锁定屏幕」→ 点左下角（或右下角）按钮上的 − 去掉手电筒 / 相机 → 点 ＋ 选「语音备忘录」。也可以加到控制中心。锁着屏能不能直接开录以你手机上实际为准；要解锁的话，看一眼手机面容 ID 就过了
- **手机已经在手上**：直接点主屏幕上的小猪，夜间会直接进录音页
- 让夜里更安静、更暗：手机保持静音（iPhone 15 拨侧面的静音开关），外观设成自动深色；「设置 → 辅助功能 → 辅助功能快捷键」选「降低白点值」，连按三下侧边按钮屏幕就更暗

**早上导入**：在语音备忘录里选中那段录音 → 分享 →「存储到文件」（存到 iCloud 云盘里一个固定的文件夹最方便）→ 打开 App「设置 → 数据 → 导入录音」，多选这几个文件 → 核对一下日期和标题 →「导入 N 段」。

- 录音时间从文件内部读出来，读不到才用文件时间，每条都会标明时间来自哪里
- 你在语音备忘录里改过名的录音，名字直接当标题；默认名（地址、「新录音 3」之类）不当标题
- 同一段录音导入两次会被认出来跳过
- 也可以选「加到已有条目」，接到当天已经写好的那条里
- 只收 `.m4a`。存储时如果选了「可编辑」，会存成 `.qta`，App 读不了，重新存一次、不选它就行
- Mac 上：把录音文件直接拖进 App 窗口也行

## 从备忘录迁移

以前记在「备忘录」里的那条长笔记可以一次搬进来，在 Mac 上做最方便。原笔记不会被改动，等同步用稳定了再决定删不删。

1. **复制笔记文字**：在 Mac「备忘录」里打开那条笔记，全选（⌘A）、拷贝（⌘C）
2. **导出录音附件**：菜单「文件 → 存储附件…」存到一个文件夹；或者把笔记里的录音一个个拖到 Finder 里
3. （可选）在备忘录里全选笔记 →「共享 › 拷贝」，得到一串录音文件的路径。粘贴进来能确定录音的先后顺序，配对更准
4. 打开 App「设置 → 数据 → 从备忘录迁移」：粘贴第 1 步的文字，App 会按「2024」这样的年份行和「5/20」这样的日期行切成一条一条，告诉你一共几条、几段录音位置；然后选第 2 步的录音文件，需要的话粘贴第 3 步的路径
5. **导入核对**：每段录音配给哪一条，都标明了依据（路径顺序 / 文件名日期 / 标题出现在原话中 / 录音时间 / 仅按顺序）。依据不足或者互相矛盾的排在最前面、标成提醒色，可以点 ▶ 试听，用下拉框改配或者选「不配录音」
6. 确认无误点「确认导入 N 条」。之后建议马上「导出备份」一次

同一份笔记再导一次也不会重复：已经有的条目会显示「已存在，跳过」，你在 App 里改过的内容不会被覆盖。笔记里的原话一个字都不改。

## 在 iPhone / iPad / Mac 上安装

iPhone / iPad 没法直接打开本地的网页文件，需要把这个仓库发布成网页（GitHub Pages）：

1. 用 GitHub Desktop 把这个仓库发布到 GitHub（Publish repository）
2. 在 GitHub 网页上打开仓库 → **Settings** → **Pages**
3. **Source** 选 `Deploy from a branch`，Branch 选 `main`、目录选 `/ (root)`，点 Save
4. 过一两分钟，页面上会显示网址，类似 `https://你的用户名.github.io/babble/`

仓库里只有程序代码，没有梦话和录音（`.gitignore` 已经排除了 `.m4a`、`.zip` 备份等文件），所以仓库公开也没关系；免费账号只有公开仓库能用 GitHub Pages。以后改了代码，在 GitHub Desktop 里 Commit、Push，过一两分钟各台设备重新打开就是新版。

然后：

- **iPhone / iPad**：用 Safari 打开上面的网址 → 分享按钮 →「添加到主屏幕」，确认「作为 Web App 打开」是开着的（新系统才有这个开关）→ 添加。之后从主屏幕的小猪打开
- **Mac**：Safari 打开网址 → 菜单「文件 → 添加到程序坞…」，之后从程序坞打开

一定要从主屏幕 / 程序坞打开再用：Safari 标签页和主屏幕 App 的数据是分开的，标签页里的数据长时间不打开还可能被系统清掉。

支持 iOS / iPadOS 18.4 或更新、Mac 上的 Safari 18 或更新，最近版本的 Chrome 也能用。系统升级不用管，App 跟着 Safari 走；换新手机时，在新手机上重新添加到主屏幕、粘贴同步码就行。

## 多设备同步（你和 NN 的所有设备）

开启后，在任何一台设备上记的、录的、整理的，其它设备打开时都会自动拿到。数据存在你自己的 GitHub 私有仓库里：`babble.json` 是全部条目和设置，`audio/` 里是录音（每次同步是一次提交，仓库的历史记录也是一份备份）。

### 第一次设置（只需要做一次）

1. 在 GitHub 上新建一个仓库，叫 `babble-data`，选 **Private**，勾上「Add a README file」
2. 打开新建令牌的页面：<https://github.com/settings/personal-access-tokens/new>
   （也就是点 GitHub 右上角的**头像** → **Settings** → 左侧栏最底下的 **Developer settings** → **Personal access tokens → Fine-grained tokens → Generate new token**。注意是账号的 Settings，不是仓库里的 Settings）
   - **Repository access** 选 **Only select repositories**，只选 `babble-data`
   - **Permissions** 里找到 **Contents**，设成 **Read and write**（新版页面可能要先点 **Add permissions**；其它都不用开）
   - 有效期可以设长一点，记一下哪天到期
3. 马上复制生成的令牌（`github_pat_` 开头，离开页面就看不到了）
4. 打开 App「设置 → 同步」，填入 `你的用户名/babble-data` 和令牌，点「连接」。App 会先确认这个仓库是私有的，不是私有的不会上传

### 其它设备（包括 NN 的）

在已经连好的设备上点「复制同步码」（`babble-sync:` 开头），用隔空投送或者通用剪贴板送到另一台设备，在那台设备的「设置 → 同步」粘贴进去点「连接」。你的 iPhone、iPad、Mac 和 NN 的 iPhone、iPad、Mac 都用**同一个同步码**，大家看到的就是同一本，谁记的都算。

### 怎么同步

- 改动后几秒钟自动上传；打开 App、切回 App、联网时，以及开着的时候每隔一分钟，会检查别的设备有没有改过
- 每次先传录音、再传文字列表，所以别的设备不会看到「有条目、录音却还没到」的情况太久
- 别的设备的录音在后台下载，最新的先下；点 ▶ 时还没下好的会优先下载
- 没网时照常用，联网后自动补传
- 两台设备都改过的话逐条合并：每一条取较新的那次修改。同一条在两台设备上同时改，会以后改的为准（不是逐字合并）
- 「设置 → 同步」能看到上次同步时间、还有几段录音待上传 / 待下载，也可以「立即同步」

### 令牌过期、安全

- 令牌的到期日在连接时填上（可选；GitHub 不把到期时间告诉网页，App 自己读不到）。填了以后「设置 → 同步」会显示，并提前两周提醒；连接时没填，也可以在那里补上。到期前在 GitHub 新建一个令牌（权限和原来一样），在一台设备的「设置 → 同步」点「换令牌」粘贴进去，不用停止同步；再点「复制同步码」，在其它每台设备上也点「换令牌」，粘贴这个新的同步码
- 令牌已经过期或者被删掉了也一样用「换令牌」；在换好之前，各台设备照常能用，改动先存在本机，换好后自动补传
- 令牌只保存在填写它的那台设备上，不会进备份文件，也不会上传到仓库
- 令牌只能访问 `babble-data` 这一个仓库；同步码里就是令牌原文，只发给自己的设备，不要发到群里
- 删掉的条目在仓库里只是标记为删除；**录音一旦同步过，就一直留在私有仓库的提交历史里**，想彻底清掉只能删掉整个 `babble-data` 仓库重新开始
- 不想用了：在每台设备上点「停止同步」，再到 GitHub 上删除这个令牌

## 备份

「设置 → 备份 → 导出备份」得到一个 zip，里面有：

- `babble.json`：全部条目和设置（整个 zip 能用「从备份恢复」导回来）
- `audio/`：全部录音，文件名带日期和录音的名字（没起名的用标题或第一句），比如 `2026-01-02 今天吃什么 (1a2b3c4d).m4a`，单独拿出来也能听
- `梦话.md`：按年、按日期排好的全部原话，任何文本编辑器都能打开

iPhone / iPad 上会弹出分享面板，可以存到「文件」或者隔空投送到 Mac。设置里会显示「上次备份 N 天前」。

「从备份恢复」是**合并**：备份里的条目和现有的逐条合并（取较新的），不会删掉现有的任何东西，恢复前会先确认。开着同步时恢复，合并结果会同步到所有设备。备份里没有令牌。

## 已知限制

- **网页 App 不能在锁屏时录音**，也不能从锁屏、操作按钮、控制中心或快捷指令直接打开（快捷指令的「打开 URL」只会开一个 Safari 标签页）。所以手机锁着时用语音备忘录录（见上面）
- 在 App 里录音时，锁屏、切到别的 App 或者来电，录音会停下。已经录到的部分不会丢：每秒都存过，回来时自动收尾；万一 App 被系统关掉，下次打开会把这段拼回来，放进「待整理」
- 每次冷启动后第一次录音，可能都要再点一次「允许」麦克风，这是 Safari 决定的
- 梦话开头那几秒一定会错过，因为要花时间拿手机
- Safari 标签页和主屏幕 App 的数据不互通；删掉主屏幕上的图标就等于删掉这台设备上的数据，所以一定要开同步或者定期备份
- 同一台设备上，你的几个网页 App（房屋账本、虚拟书架……）共用 `github.io` 这个域名的存储空间。「设置 → 存储」能看到用了多少、是否已经「持久保存」（持久保存的数据系统空间紧张时也不会自动清掉）
- 没开同步的设备上，只能播放这台设备上有的录音
- 「均衡」是在手机上现算的：Mac 上 10 分钟的录音第一次切换不到 1 秒，iPhone 上会慢一些（没有实机量过）
- 修改记录里的旧版本是每台设备自己记的，不同步；换手机、删掉主屏幕图标就没了（开了同步的话还能从云端历史找）
- 「转成文字」只在 Mac 上实测过（WKWebView / Safari），iPhone 上的速度和内存是按 Mac 的结果估的。iPhone 内存紧时 App 可能在识别中被系统关掉，下次打开会提示；先关掉别的 App 再试。识别结果难免有错，尤其是含糊、小声的梦话
- 录音相关的功能还没有在每一款 iPhone / iPad 上实机验收过，换了新设备或者大版本升级后，建议跑一遍「录音诊断」

## 录音诊断

「设置 → 录音诊断」：一项项点着测，生成一份可以复制的报告，录音出问题时最有用。测的内容：

- 是不是从主屏幕打开的、系统和浏览器版本
- 支持哪些录音格式（`audio/mp4`、`audio/webm`）
- 录 5 秒（每秒一段）→ 拼起来 → 看格式、大小、时长 → 放出来听
- 屏幕常亮能不能开
- 存储是否持久保存、用了多少空间
- 能不能把录音文件分享出去、麦克风权限状态

报告里只有设备和功能信息，没有录音内容。

## 开发检查

```sh
node --test tests/*.test.mjs
python3 -m http.server 8791 --bind 127.0.0.1
```

然后打开 `http://127.0.0.1:8791`。本地预览用的是独立的浏览器存储，不注册离线缓存（只在 https 下注册），不代表线上已安装的版本。

- 测试只用编出来的数据（比如「“今天吃什么”」「测试录音.m4a」）和模拟的同步响应，不读令牌，也不会访问或写入 GitHub
- **这个仓库是公开的**：真实的梦话、录音、录音文件名、备份都不要放进来，测试、注释、例子里也不要写
- 新加的程序文件要写进 `sw.js` 的 `CORE`（离线缓存的文件表，`tests/sw.test.mjs` 会检查）；发布新版时把 `CACHE` 的版本号加一（`babble-v2`……），旧缓存会自动清掉，只清 `babble-` 开头的，不影响同一个域名下的其它 App
- 「转成文字」用的第三方文件在 `vendor/transformers/`（transformers.js 4.3.2 和 onnxruntime-web 的 wasm，原样拷贝，版本、来源、许可见那里的 README）。它们不进 `CORE`（几十 MB），第一次用到时存进 `babble-vendor-tf432` 缓存，换版本时改 `sw.js` 的 `VENDOR_CACHE`。模型由 transformers.js 自己存在 `transformers-cache` 里，`sw.js` 不碰。识别在 `src/workers/transcribe.worker.js`（模块 worker）里跑，页面这边是 `src/core/transcribe.js`，界面在 `src/ui/stt.js`
- 网页的 CSP 为此多了 `'wasm-unsafe-eval'` 和 `https://huggingface.co https://*.hf.co`（下载模型）；本地预览时模型照样从 Hugging Face 下载
