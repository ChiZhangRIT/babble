# 牙牙呓语

专门用来记 NN 说的梦话：夜里最快地把声音录下来，白天再补上原话，几年后还能按日期或者关键词翻出来，再听一遍。

- 网页 App（PWA），不需要编译，也不用上架 App Store；部署到 GitHub Pages 就能在 iPhone、iPad、Mac 上用，添加到主屏幕 / 程序坞后和普通 App 一样打开，没网也能打开
- 梦话和录音保存在自己设备的浏览器里；开启同步后，另存一份到你自己的 GitHub 私有仓库，不经过任何第三方服务器
- 你和 NN 两个人的 iPhone、iPad、Mac 用同一个同步码，看到的是同一本
- 界面有简体中文、繁體中文（台灣）、English 三种：「设置」最上面那一行「语言 / Language」（没有小标题；繁体界面写「語言 / Language」，英文界面写「Language / 语言」）的下拉菜单里切换，选了马上换，只存在这台设备上；你写的原话永远原样保存，不做简繁转换，引号、标点也不会被「修正」

## 怎么用

底栏只有三个：**呓语**（列表 / 日历）｜ 中间的**猪鼻子**（录音）｜ **设置**。iPad 和 Mac 上换成侧栏，窗口够宽时左边列表或日历、右边详情。

### 记一条

列表上的 ＋「记一条」。日期默认今天（必填），时间可以不填。原话框上面有 `👰🏻‍♀️ NN` 和 `🥷🏻` 两个按钮，点一下就插入一行、光标停在引号中间；下面一排表情（🤯 🫨 😲 🤭 😂 🥲）插入「🥷🏻 + 表情」那一行。也可以在详情页的 `⋯` 里「添加录音（文件）」（不是 m4a 的录音先转成 m4a 再存，见下面「早上导入」）。

保存失败时会留在编辑页，保留正在写的内容和已有的恢复草稿，显示提示；清理空间后可以直接重试，不用再输入一遍。

原话就按你在备忘录里一直以来的写法写，App 会画成聊天气泡（下面是编出来的例子）：

```
👰🏻‍♀️“今天吃什么”          ← NN 说的话：左边的气泡
🥷🏻“想吃什么呀？”          ← 你问的：右边的气泡
👰🏻‍♀️ 皱了皱眉              ← 动作（没有引号）：浅浅的「动作」气泡，普通字体
👰🏻‍♀️ 指着窗外 “下雨了”     ← 混着写：引号里的楷体，引号外的动作小一点、淡一点
🥷🏻 🤯                     ← 只有表情：显示成一个大表情
过了一会儿..                 ← 不以表情开头的行：居中的小字旁白
                             ← 空一行：同一晚的两段之间隔开
```

表情带不带肤色、带不带变体符号都认得（👰‍♀️ / 👰🏻‍♀️ / 👰🏻‍♀ 都算 NN）。在「设置 → 称呼与表情」改了表情，旧的表情还会继续被认出来，以前写的不用改。

### 对话里的动作和说的话

**引号里是说的话，引号外是动作或环境**。说的话用楷体；动作、环境、旁白用普通字体，小一点、淡一点，像剧本里的舞台说明（不用斜体，中文斜体不好看）：

- 一整行都是动作（`👰🏻‍♀️ 揉了揉眼睛`）：浅浅的、没有底色的「动作」气泡，一眼就和说的话分开
- 混着写（`👰🏻‍♀️ 指着窗外 “下雨了”`）：同一个气泡里，「指着窗外」是普通字体，「“下雨了”」是楷体
- 没有表情开头的旁白（`过了一会儿..`）：居中的小字；旁白里带引号的那几个字照样是楷体
- “” 「」 『』 "" ＂＂ ‘’ 都算引号，「」里面套『』也行
- 引号没配对也认得：只写了后引号的（`她说了”`）从行首到后引号都算说的话；没写后引号的到这一行末尾都算说的话；行首或空格后面的 ” 当前引号用

详情页、列表卡片、修改记录的预览里都这样显示，深色、夜间也看得清。只是显示不一样，原话一个字都不改。

### 录音

点中间的猪鼻子进录音页：整页近黑、字很暗，不会晃醒人。点「开始录音」就开始录，默认是边录边写（见下一节）；不想写就点下面的「只录音」，录音时下面大半个屏幕都是「停止并保存」，摸黑也点得到（会记住，想写时点「边录边写」）。

- 录音时屏幕保持常亮，每秒存一小段到手机上；录满 10 分钟自动停（「设置 → 夜间 → 最长录音」可以改）
- 停下后显示「已保存 0:42」，可以「再录一段」（接到同一条里）、「稍后整理」（回去，这条留在「待整理」里，写了的字一起存好），写了字以后还有「整理好了」（这条整理完了，不再放在「待整理」里）
- 误点了「开始录音」：点左上角的 ✕（只录音时旁边写着「取消」），这段不存、也不进编辑页，回到录音前的样子（写的字还在框里；「再录一段」录的就回到上一段的「已保存」）。提示条上 10 秒内可以「撤销」，撤销就和点了「停止」一样
- ✕ 点错了、她还在说：直接再点「开始录音」就行，刚才取消的那段会留下，接着录的放进同一条
- 停下以后才发现不要：点下面的「🗑 放弃这段录音」，刚录的这段就丢掉了，回到录音前的样子（「再录一段」录的就回到上一段的「已保存」），可以接着录。刚建的那条只有这段、又没写字的话整条不要（「最近删除」里也没有）；接到已有的一条、或者已经写了字的，只拿掉这段录音，字还在。10 秒内也可以撤销
- 录好的自动建一条**待整理**，日期和时间来自录音开始的时刻（凌晨 3:10 录的就记在当天，显示「凌晨3:10」）
- 夜间时段（默认 21:00–07:00）打开 App 会直接进录音页、全 App 变深色，都可以在「设置 → 夜间」关掉
- 第一次录音要允许使用麦克风

### 边录边写

听着 NN 说梦话、一边录一边把她说的打下来：

- 录音页点「开始录音」后，顶上一条是红点、计时、音量条和「停止」，下面就是写原话的地方（和「记一条」一样有 👰🏻‍♀️ / 🥷🏻 按钮和反应表情，楷体、暗色）。光标已经在「👰🏻‍♀️ “”」的引号中间，直接打字
- 弹出键盘时「停止」也一直在最上面；打字不会打断录音
- 停下后录音和写的字存进同一条（待整理）；「再录一段」还是同一条、写字的地方不变，停了以后也能接着补
- 可以先写再点「开始录音」，写的字照样留着；写了字没录音就离开，也会存成一条待整理（可以撤销）
- 写的字随手存在手机上（每 0.4 秒、切到后台时），App 中途被系统关掉，下次打开会把字和录到的那段一起放回同一条
- 「记一条」和编辑页里也能录：原话上面的「🎙 录一段」，不离开编辑页就录，录着也能接着写。已有的条目录好就马上接上；新的一条跟着「保存」一起存，没保存就离开也会单独存成一条待整理，不会丢
- 打字的咔嗒声会被录进去、也可能吵醒 NN：「设置 → 声音与触感 → 键盘反馈」里关掉「声音」（App 的「设置 → 夜里录得更快」里也有这条提示）

### 待整理

列表顶上的「待整理 N 条」点进去：听一遍（小声的听不清可以切到「均衡」），把原话打进去，点「整理好了」。语音备忘录自带的转写可以粘贴到「草稿」里当参考，草稿永远不会覆盖原话。

### 给录音改名

详情页每段录音上面是它的名字（导入的录音默认是原来的文件名，App 里录的是「录音 1」「录音 2」）。点名字或旁边的 ✎ 就能改；空着保存就回到默认名。编辑页的录音列表里也能改（跟着「保存」一起存）。改名会同步、会记进「修改记录」。分享录音、导出备份时用这个名字当文件名（`/\:*?"<>|` 这些文件名里不能用的字符会换成空格，最长 80 个字）；没改过名的用原来的文件名，「新录音 3」这种默认名和 App 里录的用日期加 NN 的第一句。同步到 GitHub 的文件还是按内容起的名字，不会跟着改。

### 音量均衡（听不清的时候）

梦话常常一句很小声、下一句突然很大声。把播放器右边的「原声」切成「均衡」：每一句都调到差不多的音量，小声嘀咕的放大、突然很大声的压低，按手机现在的音量听，每句都差不多响，不用一会儿调大一会儿调小。

- 只影响播放，存着的录音一点不变；随时切回「原声」
- 放着的时候也能切，接着刚才的位置放。第一次切要先把整段录音处理一下（显示「处理中…」，这期间原声照常放），之后再切就是马上的
- 选过一次，以后所有录音都按这个放，列表卡片上的 ▶ 也一样（每台设备各自记）
- 小声的那几句放大时，背景的沙沙声也会跟着大一点，这是正常的

### 语音转文字（草稿，在本机识别）

有录音的条目，每段录音下面有「转成文字（草稿）」：在这台设备上用 Whisper 把录音识别成文字，**录音不会上传到任何地方**。梦话常常含糊，识别出来的只是草稿，可能写错，但能省掉从头打字的功夫。

- **第一次用要先下载模型**：从 Hugging Face 下载一次（iPhone、iPad 上标准约 76 MB；Mac 上用显卡加速时约 199 MB），存在这台设备上，之后不联网也能用。最好连着 Wi‑Fi 时先在「设置 → 语音转文字」点「现在下载」，夜里就不用等。第一次转文字时还会从本站下载 1.3 MB 的说话识别模型（和床头模式共用，用过床头模式就已经有了）。Mac 上用显卡加速时，第一次还要多下载约 14 MB（说话识别用的是处理器版的 onnxruntime，和显卡版不是同一个文件；用过床头模式、或者关掉显卡加速转过文字就已经有了），这时只显示「找说话的地方…」、没有下载进度；网很慢、一分钟下不完的话，这一次照旧只按音量找
- 识别时显示进度（找说话的地方… / 下载模型 x% / 识别中… 第 2 / 5 段），边识别边出字，随时可以「取消」；识别中可以离开这一页，做完会自己写进那一条的草稿
- 先找有人说话的地方，只把这些交给模型，每段单独识别（10 分钟的录音里只说了几句也找得到）；只有杂音、鼾声的录音会提示「没听出有人说话」，不会编出一句「谢谢观看」。被鼾声、杂音盖住的悄悄话偶尔会找不到：这时提示条上有「按音量再找一遍」，点了就用以前按音量的找法重新识别一次（杂音多的会送去更多，慢一些）
- 找说话的地方用的是床头模式那个说话识别（Silero VAD，在这台设备上跑，声音不上传）：鼾声、风扇、白噪音机的声音不再当成说话送去识别，比底噪还小声的嘀咕也更容易找到。真正安静的地方（连呼吸声、翻身声都没有）先按音量跳过，这样的长录音很快就找完；整夜都听得见呼吸、鼾声、风扇起伏的录音几乎每一段都要交给说话识别听一遍，要久一些（见下面「大概要多久」）。送去识别的少了，打鼾、开着风扇的长录音识别得更快。找得久的话（长录音）会先显示「找说话的地方…」，这时也能「取消」。说话识别用不了时（比如模型没下载下来），照旧只按音量找
- 结果只进**草稿**，原话一个字不动。草稿就在录音下面，可以直接「修改」（一边听一边改）；改好了点「填进原话」，每一行会写成 `👰🏻‍♀️“……”` 接在原话后面，再到编辑里把你自己说的那几行改成 🥷🏻。填错了可以撤销
- 一条有几段录音时，各段的结果按录音顺序拼在草稿里，中间空一行；重新识别一段只换掉那一段。草稿手动改过（或者是粘贴的语音备忘录转写）的话，新的结果接在后面，原来的不动
- 界面是简体中文时，识别结果里的繁体字会换成简体（Whisper 认出来的字本来简繁混着）；界面是繁体中文时不转换
- 模型：**标准**（whisper-base）适合 iPhone、iPad；**更准**（whisper-small）对含糊的话认得更好，但更慢、更占内存，只在 Mac 上提供（iPhone / iPad 上内存不够）。Mac 上有显卡加速（WebGPU）时会用显卡，快很多，但模型要多下载一些（标准约 199 MB、更准约 393 MB）；「设置 → 语音转文字 → 用显卡加速」可以关掉。显卡出错时自动改用处理器重来
- 不想占地方了：「设置 → 语音转文字 → 模型文件 → 删除」，以后要用会再下载
- 大概要多久：iPhone 上每段说话（最长 28 秒）约 3–4 秒，第一次还要多几秒载入模型；Mac 上用显卡不到 1 秒。找说话的地方在 Mac 上：安静的屋里每分钟录音约 20–50 毫秒；听得见呼吸声、鼾声、翻身声的（多数整夜的录音都是）每分钟约 0.3–0.4 秒（30 分钟约 10–12 秒）。iPhone 上还没量过，估计慢几倍

### 搜索

搜索框直接打字，简体繁体互通（搜「梦话」也能找到「夢話」），会搜原话、「那天的背景」、草稿和录音的名字（起的名字 / 原来的文件名）。下面的 ⭐ 收藏 / 🎙 有录音 / 待整理 可以叠加筛选。搜到的字标出来；只是背景、草稿或录音名里有的，卡片下面多一行写着是哪里搜到的。

### 列表卡片

梦话没有标题，也不用起名字：每张卡片上面是日期时间（有录音的带时长和 ▶，待整理的有标记，右上角 ⭐），下面就是**整段原话**，和详情页一样分说的话（楷体）、动作和旁白（普通字体、淡一点，旁白居中）、只有表情的反应、空行分段、「🎙 录音」小标签。

- 很长的一条（超过 16 行）先显示前 12 行，下面点「展开全部（还有 N 行）」就在原地展开，点「收起」收回去；这次打开 App 期间一直记得（点进详情再回来、换到日历都还是展开的）。搜到的字在折起来的那部分时直接展开
- 卡片上别的地方点一下还是打开这一条；▶ 直接听第一段录音
- **左右滑**（像「邮件」）：往左滑露出红色的「删除」按钮，往右滑露出黄色的「收藏」按钮（已经收藏的是「取消收藏」）。滑开只是露出按钮，要点一下按钮才会收藏或删除；滑得再远、再快，松手也只是把按钮留在那儿，不会直接删除或收藏（卡片最多拉开一个半按钮宽）。删除和详情页里的一样进「最近删除」，删除和取消收藏 10 秒内都能「撤销」。同一时间只开一张，点别处、上下滚动、按 Esc 都会关上；点开着的卡片只是关上。从屏幕最左边开始的不算（留给系统）。Mac、iPad 的触控板两指横扫也行（一样只露出按钮）。日历里那天的卡片也一样
- 还没写原话的（待整理）显示「还没写原话」
- 以前的版本里填过的标题还存着（同步、备份里都原样留着），只是不再显示、不再搜，也不会被改掉

### 按日历看

「呓语」右上角的「列表 | 日历」切到「日历」（下次打开还是日历）。

- 有梦话的日子是浅玫瑰色的圆，下面的小圆点是条数（3 条以上加「+」），右上角的小麦克风表示那天有录音；待整理的也算。今天画一圈
- 点一天，下面列出那天的梦话（和列表里一样的卡片），点进去看详情；点一个没有梦话的日子，可以直接给那天「记一条」
- ‹ › 翻月，手机上左右滑也行，「今天」回到今天；点月份标题看全年 12 个月，点哪个月就跳过去
- 这个月还没有的话，会提示最近一条在哪天，点一下就过去
- iPad、Mac 窗口够宽时，左边是日历、右边是点开的那条

### 删除

删除的条目先进「设置 → 数据 → 最近删除」，30 天内随时可以恢复；刚删完的 10 秒内也可以直接点「撤销」。恢复了的，其他设备同步时也一起恢复。

- 「最近删除」里的梦话写着有几段录音、多长；点进去只读地看原话、听录音（误录的可以先听一下再决定），也能恢复、永久删除
- 编辑页里「移除」的录音也放进「最近删除」，在「移除的录音」下面（没起名字的叫「移除的录音」）：能直接听，点名字、「来自 …」那一栏去那条，「恢复」就放回那条的最后。保存时提示条会说一声
- 删除的梦话里以前移除过的录音跟着那条走（那一行写着「另有 n 段移除的录音会一起删掉」），恢复那条时一起回来，永久删除时一起删掉
- 编辑页里这次刚加进来、还没保存就移除的录音不进「最近删除」（它还没在哪条里），在下面的「没有梦话在用的录音」里找得到

**永久删除**：「最近删除」里每一项旁边有「永久删除」，下面有「全部永久删除」（删的是页面上列着的这些）；在详情页看已删除的梦话时也能永久删除。都要先确认，删了就不能恢复，没有撤销。

会删东西的确认框（永久删除、移除录音、删除语音转文字的模型、清理云端历史、停止同步、离开没保存的编辑页……）是「取消」和红色的按钮，焦点先在「取消」上，连按两下回车不会直接删掉；按 Esc、点框外面也是取消。读屏打开确认框时会先念标题，再念那句说明（没有标题的念那句话）。

- 永久删除会把原话和录音从这台设备、其他设备和同步仓库的 `audio/` 里删掉，只留一个不含内容的记号，让每台设备都知道这一条删掉了；每台设备记的这一条的旧版本（修改记录）也一起忘掉
- 开着同步时，删之前先同步一次（最多等 10 秒），删完马上再同步；同步不上的话提示条会说一声，联网同步以后才删仓库里的文件
- 仓库里的录音文件同步时马上删（一次提交删掉）；各台设备上的录音文件先留 7 天（从永久删除那一刻算，这期间打不开、不上传、不进备份）再删：万一另一台设备同时恢复了这一条，录音还找得回来。没开同步的设备上马上删
- 同一段录音另有别的梦话在用的话，那里的照样留着，录音本身不删；草稿改过、里面有这段录音转出的字的，这些字也留着（确认框都会说：永久删除梦话、全部永久删除时说「其中 n 段录音别的梦话也在用」；一段录音也不删的时候不说「录音文件马上从同步仓库删掉」）
- 「昨夜」里还没整理、声音就是这段录音的片段，会一起删掉（确认框会说）

**30 天自动永久删除**：在「最近删除」里放满 30 天的，自动永久删除（和自己点的一样传到每台设备、从仓库里删掉）。每一项下面写着「n 天后永久删除」。

- 每台设备从它自己第一次看到这一项在「最近删除」里算起，而且不早于开放永久删除的那一刻（第一台用上这一版的设备第一次同步成功的时候，按 GitHub 服务器的时间记，这台设备的时钟快了也不会记到将来；没开同步的设备：第一次打开这一版的时候）
- 所以更新那天已经在「最近删除」里的（以前删的、误录的），从第一台设备开放那天起还有整整 30 天，不会一更新就被删掉。哪台设备先删了，照样同步到别的设备，所以晚几天才更新的设备上，剩下的天数从第一台开放那天算，不是从它自己更新那天算
- 每台设备第一次打开这一版时，「最近删除」里有东西的话，提示条会说一声：第一台开放的设备上说「从今天开始算 30 天」，晚更新的设备上说最早哪天永久删除（开着同步、还没同步成功的话，等同步成功、知道日期了再说；正好有别的提示条时等它收起）
- 删了、恢复、又删，从最后一次删重新算；恢复的梦话里以前移除过的录音，按当初移除的时间算，恢复不会重新计时（有的设备可能晚一点才删，写着的日期按早的算）
- 不会比写着的日期早删（写着的日期不会比真删的晚）；到了那天要是哪台设备都没打开，就等哪台打开了再删
- 启动时、每次同步以后、开着的时候每小时看一次有没有到期的；本机数据有问题时不删

**没有梦话在用的录音**：「最近删除」最下面一节。以前移除、导入后撤销或取消的录音（还有旧版本移除时没留记录的），可能还留在这台设备或同步仓库里，哪条梦话都没在用。

- 点「查找」才找：开着同步先同步一轮，再看仓库和这台设备。24 小时内刚传上来的（梦话可能还在路上）、一小时内刚碰过的不列；仓库里一次最多查 100 段
- 列出来的能听，可以一段段永久删除，也可以「这些录音全部永久删除」。只在这台设备上、从没上传过的会标出来，只能一段段删（删了就哪里都没有了）
- 这次打开修过数据、从备份恢复过，或者一条梦话都还没有（比如还没同步下来）时，这一节不显示：那时什么都像是没人用
- 「设置 → 存储」里也会写「其中 n 段没有梦话在用」（这台设备上的），点了直接到这一节；这一节不显示的时候（比如刚从备份恢复过）这一行也不显示

**别的设备上同时改过、恢复了的**：以改过的为准，这次永久删除不算数，App 会说一声，看一下再决定要不要再删一次。录音 7 天内都还找得回来；已经同步到这次永久删除的设备，它们自己记的那一条的旧版本不会回来（「从云端历史找更早的版本」还找得到，除非清理过云端历史），作废它的那台设备上的还在。

仓库的提交历史里还留着以前的版本（Mac 上的 `babble-data` 文件夹也是）；要彻底清掉，用「设置 → 同步」里暂停的历史清理说明（见下面「清理云端历史」）。

### 修改记录与「这台设备」

每条梦话的「⋯ → 修改记录」能看到以前的每一版：什么时候、谁、用哪台设备改的，改了原话 / 背景 / 录音 / 草稿 / 日期……原话按行标出加了什么、删了什么。点开一版能看当时的样子，「恢复这个版本」就改回去（恢复本身也能撤销，也会记成新的一版）。恢复时录音不会变少：现在的录音都留着，再放回那一版有、现在没有的（在「移除的录音」里的直接放回来）。详情页最下面有一行小字「最后修改：谁 · 哪台设备 · 什么时候」，删除的梦话在「最近删除」里也写着是谁删的。

- **这台设备**：「设置 → 这台设备」填设备名（默认是 iPhone / iPad / Mac）和「谁在用」（你或者 NN，用「称呼与表情」里的名字和表情）。只存在这台设备上，不同步。第一次在一台设备上改梦话时会问一句「这台设备是谁在用？」，也可以「以后再说」
- 旧版本保存在这台设备上（每条最多 100 版，不同步）；开了同步的话，还能点「从云端历史找更早的版本」，从数据仓库的提交记录里一版一版往前找，别的设备上改的也找得到。用过「清理云端历史」的话，只找得到清理之后的
- 以前的条目、旧版本 App 改的，详情页不写是谁改的，修改记录里写「不知道是谁改的」，不会写错人

为什么不做「改之前要输密码」：同一个同步码的设备本来就能直接改仓库里的数据，App 里的密码挡不住真想改的人，反而自己半夜改个错字也得输密码。所以换了个思路：谁改的、改了什么都记下来，改坏了、删错了随时能改回去。真要防止别人动手，靠的是同步码只给信得过的设备。

## 夜里最快的录法

网页 App 没法从锁屏、操作按钮或控制中心直接打开，一锁屏录音也会停（见「已知限制」）。所以手机锁着的时候，用系统自带的**语音备忘录**录，早上再导入，最后都进同一个「待整理」。

**操作按钮**是 iPhone 15 Pro、15 Pro Max 和 iPhone 16 及之后的机型左侧、原来静音开关位置上的那个按钮，可以设成一按就做某件事。iPhone 15 / 15 Plus 没有，还是静音开关。

- **有操作按钮的 iPhone**：「设置 → 操作按钮」选「语音备忘录」。夜里按住操作按钮就开始录，说完再按一下停，接着睡
- **iPhone 15（没有操作按钮）**：把锁屏底部的一个按钮换成语音备忘录：长按锁屏 →「自定」→「锁定屏幕」→ 点左下角（或右下角）按钮上的 − 去掉手电筒 / 相机 → 点 ＋ 选「语音备忘录」。也可以加到控制中心。锁着屏能不能直接开录以你手机上实际为准；要解锁的话，看一眼手机面容 ID 就过了
- **手机已经在手上**：直接点主屏幕上的小猪，夜间会直接进录音页
- 让夜里更安静、更暗：手机保持静音（iPhone 15 拨侧面的静音开关），外观设成自动深色；「设置 → 辅助功能 → 辅助功能快捷键」选「降低白点值」，连按三下侧边按钮屏幕就更暗

**早上导入**：在语音备忘录里选中那段录音 → 分享 →「存储到文件」（存到 iCloud 云盘里一个固定的文件夹最方便）→ 打开 App「设置 → 数据 → 导入录音」，多选这几个文件 → 核对一下日期 →「导入 N 段」。

- 录音时间从文件内部读出来，读不到才用文件时间，每条都会标明时间来自哪里
- 录音原来的文件名就是它在 App 里的名字（详情页播放器上面显示，搜索也搜得到，随时可以改），不用另外起标题
- 同一段录音导入两次会被认出来跳过（在「最近删除」里的也算）
- 也可以选「加到已有条目」，接到当天已经写好的那条里
- **都存成 m4a**：语音备忘录的 `.m4a`（里面是 AAC）原样存，一个字节不动；别的格式（WAV、MP3、CAF、AIFF……）选好以后先在这台设备上转成 m4a（AAC，24 kHz 单声道，说话时每分钟约 0.4 MB：9 秒的 48 kHz 立体声 WAV 1.8 MB 转完 62 KB，128 kbps 的 MP3 150 KB 转完 62 KB），录音不离开设备。上面写着「正在转成 m4a，还有 n 个…」，转完每一行写着转之前、之后多大，才能点「导入」。立体声、多声道的先合成一个声道（取平均）；转完先在这台设备上把 m4a 解码回来，和合成的那份单声道比一遍（时长、音量、前后没错开），对不上就不用转出来的
- 转成了的：名字还是原来的文件名（带原来的扩展名），时长按解码出来的算；m4a 里的录音时间写的是条目用的那个时间（文件里的录音时间，没有就是文件修改时间）
- 转不了的（浏览器编不了、文件解不开、超过 30 分钟、文件太大、核对不过，还有两个声道正好反相、合成一个声道就互相抵消没声了的），按原来的格式存原来的文件，名字、时长都和原来一样，那一行上写一句「这段没转成 m4a，按原来的格式存」（超过 30 分钟的写「超过 30 分钟…」）。原文件本来就很小（低码率的 MP3、里面是 AAC 的 CAF…）、转完省不了一成的也不转，写「原文件已经够小…」：再压一遍只会更糊
- 详情页、编辑页的「添加录音」也一样转（转的时候先说一句「正在转成 m4a…」，没转成的也说一句）。编辑页上转的时候点「保存」，会等转完一起存；转的时候离开会先问，确认离开的话这几段不存
- 同一个 WAV 再导一次也认得出：转出来的 m4a 不一定每次都一样，所以条目里还记着原文件的指纹（`srcSha256`），两个都比。详情页、编辑页的「添加录音」也一样认。永久删除、同步只看存下来的那份 m4a：永久删除以后再导同一个文件，和再导一段永久删除过的 m4a 一样，当成新的导进来
- 「从备忘录迁移」和恢复备份不转，原样存
- 存储时如果选了「可编辑」，会存成 `.qta`，App 读不了，重新存一次、不选它就行
- Mac 上：把录音文件直接拖进 App 窗口也行

## 床头模式（整夜放在床头自动录）

不想半夜摸手机的话：把手机（或 iPad）插上电放在床头，整夜开着床头模式那一页。听到像说话的声音就自动存一小段，早上在「昨夜」里听一遍，挑要留的。

**怎么开始**：录音页「开始录音」下面那张「🌙 床头模式」卡片，或者「设置 → 夜间 → 床头模式」。准备页上有一张清单：

- 插上电源：屏幕要亮一整夜
- 「设置 → 显示与亮度 → 自动锁定」选「永不」，亮度调到最低。App 会让屏幕常亮，万一常亮没起作用，设成「永不」屏幕也不会锁上。早上记得改回来（结束那一屏也会提醒）
- 关掉低电量模式：开着时自动锁定固定 30 秒，选不了「永不」
- 打开「勿扰模式」（或睡眠专注模式），免得通知横幅在黑屏上亮起来、发出声音
- 放得离 NN 的枕头近一点，别盖住麦克风
- 「到 早上7:00 自动结束」默认开着：时间是「设置 → 夜间」里夜间时段的结束时间，赶在闹钟前停下、放开麦克风。不想自动结束就在准备页关掉（每台设备各自记）
- **第一次用要下载约 16 MB 的说话识别文件**（模型 1.3 MB，加上和「转成文字」共用的程序文件），最好白天连着 Wi‑Fi 先打开一次准备页，看到「说话识别：准备好了」就行，之后不联网也能用。下载不了的时候也能开，只是只按音量找，片段会多一些

点「开始床头模式」后整屏是纯黑的，只有一小块很暗的字：「在听 · 晚上11:41 开始 · 存了 2 段」，每分钟换个位置（免得烙印），不闪、没有秒数。要结束就**按住**下面的「按住结束」2 秒，点一下不会结束。结束那一屏写着听了多久、存了几段（有片段没存进这台设备的话也会说），并提醒把自动锁定改回来。

- 片段写不进这台设备时（存储出错），那块暗字下面会写「片段存不进这台设备了」，这条警告排在别的前面；「存了 n 段」只算声音真的存进来的
- 锁屏、来电、Siri、闹钟、别的 App 占用麦克风时会停下，屏幕上写「暂停了：原因」，好了会自己接着听；有时系统要求点一下才能接着听，整屏会变成「点一下，接着听」
- 离开这一页（返回、点了别的地方）会先问一句，离开就不听了
- App 半夜被系统关掉的话，下次打开时会把那晚收好尾（已经存的片段都在），录音页的床头模式卡片上写着「凌晨2:10 断了，点这里接着听」
- 开着的时候不自动同步；正在「转成文字」时不能开始（两个一起太占内存）

**存下来的是什么**：

- 每段从说话前 8 秒开始，到最后一句之后 2 秒；20 秒内又说话就接在同一段里，一段最长 10 分钟（还在说就接着存下一段，不丢中间的）
- 「像不像说话」由 Silero VAD 模型在这台设备上判断，声音不上传。很安静的屋里，交给它判断的那份声音先按噪声底放大（最多 30 dB，不削顶；存下的还是原来的声音），小声嘀咕也认得出；大声说完以后它会对紧跟着的小声回话变迟钝，所以说完话 2 秒没听到说话就把它的状态清一次
- 模型用不了时只按音量找，片段会多一些，早上的记录里会写；这时一开始最多存今晚额度的 1/4，听得越久放开得越多（8 小时放满），一阵鼾声用不完一晚的额度：超了就先只数次数，安静下来再接着存。这份额度只算按音量时存下的（模型半夜才用不了的话，之前存的不占它）
- 连着 3 分钟以上一直有声音（电视、风扇、白噪音）当成噪音：只存前 3 分钟，标「一直有声音」
- 一晚最多存 60 分钟的片段（这台设备空间不够时更少，准备页会写「今晚最多存 n 分钟」）；存满以后只数又听到几次、不存声音

**早上整理（「昨夜」）**：列表（或日历）顶上多一张卡片「昨夜 · 存了 3 段待听」，点进去；以前几晚在「设置 → 夜间 → 最近几晚」。

- 上面是这一晚的记录：几点听到几点、听了多久（百分比）；哪些时候没在听、为什么（30 秒以上的一条条写，短的合成一句）；「这晚还有」：一直有声音、存满了、没用上说话识别的时候（这些时候其实在听；只按音量时一阵阵存得太快的，隔不到半小时的合成一行）。一段都没存到时也会说清楚：整夜都在听没听到说话，还是几点就停了（锁屏以后被系统关掉的，写的是「屏幕锁上了」）、有一段时间没在听
- 片段按前后间隔分组，每段一个完整的播放器（可以切「均衡」）
- 勾上要留的，点下面的「留下选中的 n 段」：勾一段就是一条，勾几段就合成一条（每段是一个录音，名字是开始的时刻），放进「待整理」，再像平常一样补原话。刚留下的 10 秒内可以在提示条上撤销；撤销了，那几段会回到待听，那条和别的删除一样进「最近删除」（再留同样这几段会把它恢复，不会多一条）。留下以后又把那条删了（在这台或别的设备上），就算不要了，不会再回到待听
- ✕ 删一段；没有要留的就点「其余都删」或「昨夜没有梦话」。删掉的 24 小时内在「已删掉」里能恢复
- 「详细记录」里有「复制摘要」（几点断过、为什么、设备和采集信息，不含录音）和「导出记录文件」（JSON，排查用）。这两样只放在自己的笔记里，**不要放进这个仓库**

**片段只在这台设备上**：存在这台设备单独的一个库里，不同步、不进备份；没留下的 7 天后自动删掉声音，一晚的记录 30 天后删掉。所以要在床头那台设备上整理。只有点了「留下」的才变成条目、才会同步；每次留下以后先等 10 秒（还能撤销的时候）才同步，离开这一页也一样。第一次留下时会提醒一句：以后永久删除这条，仓库里的文件也会删掉，但提交历史里还有，要用「设置 → 同步」里暂停的历史清理说明清掉。永久删除留下的那条，会连这台设备上那几段的声音一起删掉（开着同步的话等云端确认了就删，不像录音文件那样再留 7 天：万一永久删除作废了，找回录音靠的是录音文件，用不上片段；「昨夜」里写「留下过，那条已永久删除」，不能再留一次）；留下后点了「撤销」的也一样认得出来：「昨夜」里还没整理的那几段写「这段的录音已经永久删除了」，不能放、不能再留、不算待听，声音也会删掉（永久删除的确认框会说一声）。别的设备永久删除的也一样。

留下的录音存成 m4a（AAC，16 kHz 单声道，每分钟约 0.3 MB，一段 20 秒约 100 KB，是 WAV 的六分之一）：存之前在这台设备上解码回来核对一遍，时长、音量（很轻的悄悄话也一小段一小段地比）都对得上、前后没有错开才存；浏览器编不了 m4a、或者核对不过，就照旧存 WAV（每分钟约 1.9 MB）。以前的版本留下的 WAV 原样不动，不改存成 m4a。床头模式**还没有在 iPhone 上整夜实测过**，头几晚请当成试用，早上看看记录里有没有断、断在哪里。

## 从备忘录迁移

以前记在「备忘录」里的那条长笔记可以一次搬进来，在 Mac 上做最方便。原笔记不会被改动，等同步用稳定了再决定删不删。

1. **复制笔记文字**：在 Mac「备忘录」里打开那条笔记，全选（⌘A）、拷贝（⌘C）
2. **导出录音附件**：菜单「文件 → 存储附件…」存到一个文件夹；或者把笔记里的录音一个个拖到 Finder 里
3. （可选）在备忘录里全选笔记 →「共享 › 拷贝」，得到一串录音文件的路径。粘贴进来能确定录音的先后顺序，配对更准
4. 打开 App「设置 → 数据 → 从备忘录迁移」：粘贴第 1 步的文字，App 会按「2024」这样的年份行和「5/20」这样的日期行切成一条一条，告诉你一共几条、几段录音位置；然后选第 2 步的录音文件，需要的话粘贴第 3 步的路径
5. **导入核对**：每段录音配给哪一条，都标明了依据（路径顺序 / 文件名日期 / 文件名出现在原话中 / 录音时间 / 仅按顺序）。依据不足或者互相矛盾的排在最前面、标成提醒色，可以点 ▶ 试听，用下拉框改配或者选「不配录音」
6. 确认无误点「确认导入 N 条」。之后建议马上「导出备份」一次

同一份笔记再导一次也不会重复：已经有的条目会显示「已存在，跳过」，你在 App 里改过的内容不会被覆盖。笔记里的原话一个字都不改。

## 在 iPhone / iPad / Mac 上安装

iPhone / iPad 没法直接打开本地的网页文件，需要把这个仓库发布成网页（GitHub Pages）：

1. 用 GitHub Desktop 把这个仓库发布到 GitHub（Publish repository）
2. 在 GitHub 网页上打开仓库 → **Settings** → **Pages**
3. **Source** 选 `Deploy from a branch`，Branch 选 `main`、目录选 `/ (root)`，点 Save
4. 过一两分钟，页面上会显示网址，类似 `https://你的用户名.github.io/babble/`

仓库里只有程序代码，没有梦话和录音（`.gitignore` 已经排除了 `.m4a`、`.zip` 备份等文件），所以仓库公开也没关系；免费账号只有公开仓库能用 GitHub Pages。以后改了代码，在 GitHub Desktop 里 Commit、Push，过一两分钟各台设备重新打开就是新版。

「设置 → 关于」写着现在用的是哪一版（比如「版本 babble-v32」，就是 `sw.js` 的 `CACHE`）。打开 App 时、从别的 App 切回来时（最多半小时一次）会去网站上看有没有新版；新版在后台下载、校验好以后，「关于」里会写「新版本已经下载好了：关掉牙牙呓语再打开就是新版。」（Mac 上要关掉所有牙牙呓语的窗口）。第一次安装、已经用上新版的时候不会这样说。

然后：

- **iPhone / iPad**：用 Safari 打开上面的网址 → 分享按钮 →「添加到主屏幕」，确认「作为 Web App 打开」是开着的（新系统才有这个开关）→ 添加。之后从主屏幕的小猪打开
- **Mac**：Safari 打开网址 → 菜单「文件 → 添加到程序坞…」，之后从程序坞打开

一定要从主屏幕 / 程序坞打开再用：Safari 标签页和主屏幕 App 的数据是分开的，标签页里的数据长时间不打开还可能被系统清掉。

支持 iOS / iPadOS 18.4 或更新、Mac 上的 Safari 18 或更新，最近版本的 Chrome 也能用。系统升级不用管，App 跟着 Safari 走；换新手机时，在新手机上重新添加到主屏幕、粘贴同步码就行。

## 多设备同步（你和 NN 的所有设备）

开启后，在任何一台设备上记的、录的、整理的，其它设备打开时都会自动拿到。数据存在你自己的 GitHub 私有仓库里：`babble.json` 是全部条目和设置，`audio/` 里是录音（每次同步是一次提交，仓库的历史记录也是一份备份；用「设置 → 同步」里暂停的历史清理说明清理过的话，就只剩清理以后的）。

### 第一次设置（只需要做一次）

1. 在 GitHub 上新建一个仓库，叫 `babble-data`，选 **Private**，勾上「Add a README file」
2. 打开新建令牌的页面：<https://github.com/settings/personal-access-tokens/new>
   （也就是点 GitHub 右上角的**头像** → **Settings** → 左侧栏最底下的 **Developer settings** → **Personal access tokens → Fine-grained tokens → Generate new token**。注意是账号的 Settings，不是仓库里的 Settings）
   - **Repository access** 选 **Only select repositories**，只选 `babble-data`
   - **Permissions** 里找到 **Contents**，设成 **Read and write**（新版页面可能要先点 **Add permissions**；其它都不用开）
   - 有效期可以设长一点，记一下哪天到期
3. 马上复制生成的令牌（`github_pat_` 开头，离开页面就看不到了）
4. 打开 App「设置 → 同步」，填入 `你的用户名/babble-data` 和令牌，点「连接」。App 会先确认这个仓库是私有的，不是私有的不会上传

### 其它设备（包括 NN 的）

在已经连好的设备上点「复制同步码」（`babble-sync:` 开头），用隔空投送或者通用剪贴板送到另一台设备，在那台设备的「设置 → 同步」粘贴进去点「连接」。你的 iPhone、iPad、Mac 和 NN 的 iPhone、iPad、Mac 都用**同一个同步码**，大家看到的就是同一本，谁记的都算。

### 怎么同步

- 改动后几秒钟自动上传；打开 App、切回 App、联网时，以及开着的时候每隔一分钟，会检查别的设备有没有改过
- 每次先拿别的设备的改动、合并好，再传录音，最后传文字列表：别的设备不会看到「有条目、录音却还没到」的情况太久；别的设备上删掉的录音也不会因为这台设备旧了又传上去
- 别的设备的录音在后台下载，最新的先下；点 ▶ 时还没下好的会优先下载
- 没网时照常用，联网后自动补传
- 两台设备都改过的话逐条合并：每一条取较新的那次修改。同一条在两台设备上同时改，会以后改的为准（不是逐字合并）
- 「设置 → 同步」能看到上次同步时间、还有几段录音待上传 / 待下载 / 待从仓库删除，也可以「立即同步」
- 床头模式开着时不自动同步（整夜不打扰），结束后马上补上；「昨夜」里刚留下的录音等 10 秒（还能撤销的时候）再传；这期间点「立即同步」照样会同步
- 录音页刚录好的录音先等 2 分钟再传（离开录音页、锁屏或者切到别的 App 就不再等），免得还没来得及点「放弃这段录音」就传上去了；开着别的标签页的话，它们也一起等；这期间点「立即同步」照样会同步
- **已更新到新版的设备**：每台设备用上这一版、同步成功以后，会在同步的数据里报到（设备名、谁在用、什么时候），「设置 → 同步」列出报过到的，还有最近改过梦话、或者还在用旧版本同步、却还没报到的设备。按设备名认：两台都叫 iPhone 的分不清，可以在「设置 → 这台设备」里各起一个名字。没更新的设备，关掉它上面所有牙牙呓语的窗口再打开就会更新
- 永久删除（自己点的、30 天到期的）是这样传开的：删的那台设备把条目换成不含内容的记号，同步上去；别的设备同步到这个记号，就删掉自己这里的旧版本，录音再过 7 天删（见上面「删除」），床头模式的片段确认了就删；仓库里的录音文件，要等仓库里的 `babble.json` 已经是删掉以后的样子，才由同步的设备用一次提交删掉。没联网的设备下次同步时补上

### 令牌过期、安全

- 令牌的到期日在连接时填上（可选；GitHub 不把到期时间告诉网页，App 自己读不到）。填了以后「设置 → 同步」会显示；连接时没填，也可以在那里补上。离到期不到 14 天（按日历日算，今天到期算 0 天）或者已经过期时，「设置」里「同步」那一行和侧栏的同步状态变成黄色的「令牌快到期」（鼠标停在侧栏的状态上能看到还有几天），「设置 → 同步」写「还有 n 天：到期前在 GitHub 新建一个令牌，点「换令牌」换上。」（当天写「今天到期」，过了写「已经到期了」）；同步真出了错（比如 GitHub 已经不认这个令牌）时还是红色的「同步出错」。到期前在 GitHub 新建一个令牌（权限和原来一样），在一台设备的「设置 → 同步」点「换令牌」粘贴进去，不用停止同步；再点「复制同步码」，在其它每台设备上也点「换令牌」，粘贴这个新的同步码
- 令牌已经过期或者被删掉了也一样用「换令牌」；在换好之前，各台设备照常能用，改动先存在本机，换好后自动补传
- 令牌只保存在填写它的那台设备上，不会进备份文件，也不会上传到仓库
- 令牌只能访问 `babble-data` 这一个仓库；同步码里就是令牌原文，只发给自己的设备，不要发到群里
- 删除（进「最近删除」）的条目在仓库里只是标记为删除，原话和录音都还在；永久删除（自己点的、30 天到期的）以后，原话从 `babble.json` 里去掉，录音文件从 `audio/` 里删掉
- 但**提交历史里还留着以前的每一版**（原话和录音都在）。要彻底清掉，用下面的「清理云端历史」；不然只能删掉整个 `babble-data` 仓库重新开始
- 床头模式只有点了「留下」的片段才会上传，存成 m4a（20 秒约 100 KB；以前的版本留下的是 WAV，20 秒约 640 KB），和别的录音一样同步过就留在提交历史里（永久删除以后也要清理云端历史才清得掉）。没留下的片段从不上传
- 不想用了：在每台设备上点「停止同步」，再到 GitHub 上删除这个令牌

### 清理云端历史（暂时停用）

为防止覆盖另一台设备刚上传的内容，当前版本停止重写远端提交历史：设置页只显示说明，底层 `sync.squash()` 也拒绝执行，不发送请求。普通同步、历史查看、永久删除当前版本里的条目和录音仍可使用。

GitHub 的强制更新分支接口不能原子地要求「分支仍是我刚读到的那一版」；先核对、再更新仍有并发窗口。因此不能仅增加一次检查或依赖其他设备以后重新上传来保证不丢数据。恢复此功能前需要设计并验证可靠的并发方案。

永久删除后的旧原话和录音仍可能在仓库的历史提交、已有备份里，不能把当前版本里的删除理解为清除了历史。旧版本已经清理过历史的，现有的 Mac 文件夹迁移提示仍保留。

## 备份

「设置 → 备份 → 导出备份」得到一个 zip，里面有：

- `babble.json`：全部条目和设置（整个 zip 能用「从备份恢复」导回来）
- `audio/`：全部录音，文件名带日期和录音的名字（没起名的用 NN 的第一句），比如 `2026-01-02 今天吃什么 (1a2b3c4d).m4a`，单独拿出来也能听
- `梦话.md`：按年、按日期排好的全部原话，任何文本编辑器都能打开

iPhone / iPad 上会弹出分享面板，可以存到「文件」或者隔空投送到 Mac。设置里会显示「上次备份 N 天前」。

「从备份恢复」是**合并**：备份里的条目和现有的逐条合并（取较新的），不会删掉现有的任何东西，恢复前会先确认。开着同步时恢复，先同步一次，合并结果会同步到所有设备。备份里没有令牌。「最近删除」里的条目和移除的录音（这台设备上有的）也在备份里。

永久删除过的条目和录音不会因为「从备份恢复」回来（开着同步时先同步一次，别的设备刚永久删除的也算上；确认框里会说有几段录音不恢复）。但导出过的 zip 里还有当时的原话和录音，不要了要自己删掉。备份里有、现在哪条梦话都没在用的录音也会存回这台设备（不上传），下次打开 App 以后在「最近删除 → 没有梦话在用的录音」里找得到（恢复的那次打开里这一节不显示）；恢复回来、这台设备上原来没有的「最近删除」里的东西，从恢复那天起算 30 天。

### 本机数据损坏时

如果文字数据或写入日志损坏，App 会进入恢复页面，暂停编辑、同步和自动恢复录音，不会把损坏数据当成一本空白的记录继续保存。本机录音和未收尾的录音分片仍会保留。

先点「下载原始数据」留一份文字原件（不含录音和同步令牌；里面可能有已经删除、永久删除过的原话，用完删掉），再选「从备份恢复」「从云端恢复」，或确认只保留仍可读取的记录。恢复会合并完好的记录，并在替换前先存档原始内容；存档或写入失败时不会清掉原件。恢复成功后，「设置 → 数据」仍可以下载恢复前的原始数据。

## 已知限制

- **网页 App 不能在锁屏时录音**，也不能从锁屏、操作按钮、控制中心或快捷指令直接打开（快捷指令的「打开 URL」只会开一个 Safari 标签页）。所以手机锁着时用语音备忘录录（见上面）
- 在 App 里录音时，锁屏、切到别的 App 或者来电，录音会停下。已经录到的部分不会丢：每秒都存过，回来时自动收尾；万一 App 被系统关掉，下次打开会把这段拼回来，放进「待整理」
- 点了 ✕ 取消或者「放弃这段录音」、10 秒还没过 App 就被关掉的话，下次打开那段还会回来：放回原来那条，或者「待整理」（宁可多留一条，自己再删）
- 「放弃这段录音」的那段要是已经传上去了（比如刚点过「立即同步」、锁过屏，或者正好在同步），就和平常删除一样：整条的进「最近删除」，接上的从那条里拿掉、放进「最近删除 → 移除的录音」，仓库的提交历史里还在
- 每次冷启动后第一次录音，可能都要再点一次「允许」麦克风，这是 Safari 决定的
- 梦话开头那几秒一定会错过，因为要花时间拿手机
- Safari 标签页和主屏幕 App 的数据不互通；删掉主屏幕上的图标就等于删掉这台设备上的数据，所以一定要开同步或者定期备份
- 同一台设备上，你的几个网页 App（房屋账本、虚拟书架……）共用 `github.io` 这个域名的存储空间。「设置 → 存储」能看到用了多少、是否已经「持久保存」（持久保存的数据系统空间紧张时也不会自动清掉）
- 没开同步的设备上，只能播放这台设备上有的录音
- 「均衡」是在手机上现算的：Mac 上 10 分钟的录音第一次切换不到 1 秒，iPhone 上会慢一些（没有实机量过）
- 修改记录里的旧版本是每台设备自己记的，不同步；换手机、删掉主屏幕图标就没了（开了同步的话还能从云端历史找）
- 「转成文字」只在 Mac 上实测过（WKWebView / Safari），iPhone 上的速度和内存是按 Mac 的结果估的；找说话的地方只在 Mac 上用合成的鼾声、风扇声和电脑朗读量过。有人说话的同时正好有很响的鼾声、翻身声，被盖住的那一截可能跳过不识别；单独一声很短的「唔」「嗯」有时找不到（这种 Whisper 本来也很少认出字）。iPhone 内存紧时 App 可能在识别中被系统关掉，下次打开会提示；先关掉别的 App 再试。识别结果难免有错，尤其是含糊、小声的梦话
- 录音相关的功能还没有在每一款 iPhone / iPad 上实机验收过，换了新设备或者大版本升级后，建议跑一遍「录音诊断」
- **床头模式要屏幕一直亮着、那一页一直在前台**：锁屏、切到别的 App 就停（回来会接着听，没在听的那段早上的记录里写着），App 被系统关掉的话要等下次打开才能接着听
- 床头模式遇到来电、Siri、闹钟、别的 App 录音会暂停，好了自己接着听，有时要点一下屏幕。记录里写的「来电」是猜的：网页只知道麦克风被占用了，不知道被谁占用
- 床头模式判断「像说话」的参数还在调：目前只用合成的声音和电脑朗读试过，没在真的梦话上试过，可能漏掉很小声的嘀咕，也可能存进几段鼾声
- 床头模式还没有在 iPhone 上整夜实测过（目前只有模拟测试，说话识别模型、「留下」存 m4a 在 Mac 的 WebKit 里试过）；iPhone 上整夜开着的耗电、发热、会不会被系统关掉都还不知道
- 永久删除删的是 App 管得到的地方：各台设备、同步仓库。导出过的备份 zip、「下载原始数据」的文件、Mac 上的 `babble-data` 文件夹、iPhone 自己的 iCloud 备份里的不会跟着删
- 永久删除要每台设备都同步过才算删干净：一直没联网的设备，联网同步以前它那里的还在
- 永久删除时另一台设备正好改过、恢复了这一条，以改过的为准，这次永久删除不算数（App 会说一声，可以再删一次）。录音要是那台设备从来没有、又过了 7 天才联网恢复的，就找不回来了；已经同步到这次永久删除的设备上，那一条的旧版本（修改记录）不会回来
- 还在用旧版本的设备（比如很久没打开的 iPad）可能把永久删除的内容暂时传回仓库（新版的设备同步时会再删掉）；旧版本的「最近删除」里会多出几行空白的（「还没写原话」，日期是永久删除那天），别在旧版本里恢复它们、往里写字，写的字会丢。连着网打开那台设备，等一会儿（新版在后台下载），关掉它上面所有牙牙呓语的窗口再打开，就是新版了。它用旧版本往仓库传过一次以后，「最近删除」顶上、「设置 → 同步」和永久删除确认框里都会写出它的名字；60 天内在它上面改过梦话的话，「设置 → 同步 → 已更新到新版的设备」里它也列在「还没报到的设备」下面。请先让这些设备更新；当前版本已暂停「清理云端历史」
- 永久删除以后，空间不一定马上腾出来：开着同步时，这台设备上的录音要等同步确认、再过 7 天才删，一小时内刚碰过的录音等一等再删
- 导入时转 m4a 只在 Mac 的 WebKit（WKWebView）里用电脑朗读做的 WAV、MP3、CAF 试过：10 秒的不到 0.2 秒，10 分钟的 48 kHz 立体声 WAV（115 MB → 2.8 MB）3.4 秒，29 分钟的 8 kHz WAV 18 秒。iPhone 上会慢一些、长的文件很占内存（30 分钟立体声解码出来有几百 MB），所以超过 30 分钟的、大于 400 MB 的、读不出多长又大于 16 MB 的、声道多的长 WAV 都不转、按原来的格式存；一次只转一个，并按移动设备约 96 MB、桌面约 384 MB 的 PCM 预估预算提前跳过转换，移动设备上时长未知且超过 4 MB 的也保留原文件。iPhone 的真实峰值内存仍待验收。以前导入的 WAV、MP3 原样不动，不会改存成 m4a

## 录音诊断

「设置 → 录音诊断」：一项项点着测，生成一份可以复制的报告，录音出问题时最有用。测的内容：

- 是不是从主屏幕打开的、系统和浏览器版本
- 支持哪些录音格式（`audio/mp4`、`audio/webm`）
- 录 5 秒（每秒一段）→ 拼起来 → 看格式、大小、时长 → 放出来听
- 屏幕常亮能不能开
- 存储是否持久保存、用了多少空间
- 能不能把录音文件分享出去、麦克风权限状态

报告里只有设备和功能信息，没有录音内容。

## 本轮可靠性修复与真机验收

- 床头记录库打开时同步抛错、接口暂不可用，都不会永久缓存那次失败；恢复后可以重新连接。
- 大文件的 SHA-256 以 1 MB 分块计算，不整份读取。导入文件先读取头部和 MP4 元数据盒子，跳过音频正文；尾部的 moov 也能读取。元数据总量限制为 8 MB。
- 导入保留 File/Blob 引用，不另建整份内存副本。转换前还会按声道数、时长和目标采样率预估 PCM：移动设备最多约 96 MB、桌面约 384 MB；超过就按原文件保存。移动设备上读不出时长且超过 4 MB 的文件也不自动解码转换。
- 批量「留下」先逐段核对声音存在，再一段段读取、转换、存盘；中途失败不建不完整的条目，已准备好的录音留在本机，重试时复用。
- 自动化回归不能验证真实麦克风、热量和耗电。iPhone 整夜验收步骤及空白记录表见 [docs/night-validation.md](docs/night-validation.md)。目前真机整夜验收仍是**未完成**。
